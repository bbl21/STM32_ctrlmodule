# 96 位数据位映射定义

## 硬件架构

```
PC CDC (12字节=96位)
  → STM32F103 SPI1 (6×16位, MSB first)
  → 74HC595 移位寄存器链 (串转并, 96位并行输出)
  → 3× D-sub 37芯接插件 (每个: 5×GND + 32×数据线)
  → 子模块 J30J 接插件
```

### D-sub 37 芯接插件引脚定义

每个 D-sub 37 芯：
| 引脚范围 | 功能 |
|---------|------|
| 1-5     | GND (共地) |
| 6-37    | 32 位数据线 |

---

## CDC → SPI 映射算法 (核心)

### 黑箱行为

**PC 输入 96 位 → MCU 处理后 → 595 输出 96 位 = 一一对应。**

具体地说，PC 发过来的 96 位数据中第 N 位（从 0 开始计数），经过 MCU 处理后，最终落到物理连线上第 N 个输出位（D-sub 各接插件引脚6-37 顺序排列）。

关键在于算法补偿了 CDC 字节序和 SPI 硬件时序之间的差异，使 PC 视角无需关心底层细节。

### 逐级映射详解

#### 第 1 层：PC 字节 → received_data[]

PC 发送 12 个字节（96 位），按 USB CDC 流顺序存入 `received_data[0..11]`。

```
PC 发送字节顺序:  byte0  byte1  byte2  ...  byte11
                         ↓
MCU 接收数组:  received_data[0..11]
```

#### 第 2 层：received_data[] → nibble 交换 + 组内逆序

每 4 字节为一组（共 3 组），组内执行：

```
原始字节: [b0] [b1] [b2] [b3]
                ↓  reverse_nibble()
nibble 交换: [rn(b0)] [rn(b1)] [rn(b2)] [rn(b3)]
                ↓  组内逆序组合
SPI 字:  spi_buffer[2i]   = rn(b3):rn(b2)   (高16位)
          spi_buffer[2i+1] = rn(b1):rn(b0)   (低16位)
```

`reverse_nibble()` 函数：

```c
// 输入:  0x1K  (高4位=1, 低4位=K)
// 输出:  0xK1  (高4位=K, 低4位=1)
static uint8_t reverse_nibble(uint8_t byte) {
    return ((byte & 0x0F) << 4) | ((byte & 0xF0) >> 4);
}
```

#### 第 3 层：spi_buffer[] → SPI 发送 (MSB first)

依次发送 6 个 16 位字，每个字 MSB first（先发高位，后发低位）。

```
SPI 线上 bit 流顺序:
buf[0].b15 → ... → buf[0].b0 → buf[1].b15 → ... → buf[1].b0
→ buf[2].b15 → ... → buf[5].b15 → ... → buf[5].b0
```

#### 第 4 层：SPI 位流 → 595 链 → 并行输出

74HC595 是串入并出移位寄存器，链式级联。**最先移入的 bit 到达链尾（最远一级 595），最后移入的 bit 停在链头（最近一级 595）。**

```
SPI 位流顺序 (时间先后)
  先发送 ───── buf[0].b15 → ... → buf[5].b0 ───── 后发送
               ↓                          ↓
          最远一级 595  ← ... ←  最近一级 595
          (D-sub3.pin37)          (D-sub1.pin6)

物理输出对应:
  D-sub1.pin6   ← LSB(buf[5])  ← 最近 595 的第 0 位
  D-sub1.pin7   ← bit1(buf[5]) ← 最近 595 的第 1 位
  ...
  D-sub3.pin37  ← MSB(buf[0])  ← 最远 595 的第 15 位
```

### 验证：PC 输入 "1000" → 输出 "0001"

以 4 位为例演示 nibble 补偿：

```
PC 发送 1 字节:  0x80  (二进制 1000 0000)
      高4位=1000, 低4位=0000

reverse_nibble(0x80):
  高4位 ← 原低4位 = 0000
  低4位 ← 原高4位 = 1000
  → 0x08  (二进制 0000 1000)

nibble "1000" 从高4位 → 低4位 = 0001 ← 输出映射
```

物理结果：PC 送的高 nibble "1000" 经由 nibble 交换后变为低 nibble，落在 D-sub 对应引脚上。从 PC 视角看，"1000" 输入对应的是同一个物理引脚上的 "1"，完成了 1:1 映射。

### 完整对应表

**96 位数据 → D-sub 引脚对照（按物理输出位置，从近到远）：**

| 输出位序 | 数据位标号 | D-sub 引脚 | 来源 |
|---------|-----------|-----------|------|
| 0       | bit[0]    | D-sub1.pin6  | `received_data[8]` nibble 交换后的 bit0 |
| 1       | bit[1]    | D-sub1.pin7  | `received_data[8]` nibble 交换后的 bit1 |
| ...     | ...       | ...          | ... |
| 31      | bit[31]   | D-sub1.pin37 | `received_data[11]` nibble 交换后的 bit7 |
| 32      | bit[32]   | D-sub2.pin6  | `received_data[4]` nibble 交换后的 bit0 |
| ...     | ...       | ...          | ... |
| 63      | bit[63]   | D-sub2.pin37 | `received_data[7]` nibble 交换后的 bit7 |
| 64      | bit[64]   | D-sub3.pin6  | `received_data[0]` nibble 交换后的 bit0 |
| ...     | ...       | ...          | ... |
| 95      | bit[95]   | D-sub3.pin37 | `received_data[3]` nibble 交换后的 bit7 |

> 注：transmit 后拉高 PB5 (STCP) 产生上升沿锁存，将移位寄存器内容并行输出到 595 输出引脚。

## GND 分配

每个 D-sub 37 芯接插件固定提供 5 根 GND 线（引脚 1-5）到子模块侧。

子模块 GND 需求：

| 子模块 | J30J 自带 GND | 需从 D-sub 获取 | 说明 |
|--------|--------------|----------------|------|
| 参考频模 15芯 J30J | 引脚 5,6,13 (3路) | D-sub1 至少 1 路 | 其余走模块内部共地 |
| 参考频模II 21芯 J30J | 引脚 4-8,15,18 (7路) | D-sub1 至少 1 路 | 模块内 GND 充足 |
| 25频模 25芯 J30J | 引脚 4-9 (6路) | D-sub2/3 至少 1 路 | 每路 25 频模需独立 GND |
| 9芯功放 9芯 J30J | 引脚 4,5,8,9 (4路) | D-sub3 至少 1 路 | 纯供电模块 |

D-sub 接插件上所有 GND 引脚 (1-5) 在控制模块内部共地。
